# Dubai Spares CIS — Полная архитектура UX/UI

## 1. Продуктовая идея интерфейса

Приложение — мобильная операционная CRM/PWA для команды автозапчастей, где весь пользовательский опыт построен вокруг цикла:

1. Получить лид/заявку.
2. Создать и обработать заказ.
3. Найти варианты деталей у поставщиков.
4. Подготовить и отправить клиенту коммерческое предложение.
5. Вести коммуникации, статусы и контроль исполнения.

UX разделён на две большие зоны:

- **Внутренняя (операционная)** — для менеджеров и команды закупки.
- **Внешняя (публичная)** — для клиента (заявка и просмотр итоговой сметы по ссылке).

## 2. Информационная архитектура (IA)

### 2.1 Верхний уровень модулей

- **Orders** — список и приоритизация заказов.
- **New Order** — создание заказа (быстрый/полный режим).
- **Order Details** — центр управления сделкой.
- **Order Parts** — агрегатор деталей конкретного заказа.
- **Part Details** — карточка детали и офферов поставщиков.
- **Suppliers Database** — CRM поставщиков.
- **Variants Library** — библиотека ценовых вариантов.
- **Vendor Slides** — дашборд запуска “слайдов” по фильтрам.
- **Vendor Slider** — последовательный просмотр/обработка слайдов.
- **Notifications** — центр событий и напоминаний.
- **Settings** — технические и бизнес-настройки.
- **Public Order Form** — клиентская форма создания запроса.
- **Public Quote** — публичное коммерческое предложение.

## 3. Глобальный layout и навигация

## 3.1 Мобильный shell

- Контейнер адаптирован под мобильный viewport с safe-area inset.
- Основной контент прокручивается в пределах `main`.
- Есть сохранение/восстановление scroll-позиций при переходах между экранами.
- Поддержка “живого” состояния вкладок: при возвращении пользователь попадает на ранее открытую глубину вкладки.

## 3.2 Нижняя таб-навигация

Фиксированная панель с 5 интерактивными элементами:

1. **Заказы**
2. **Поставщики**
3. **Новый** (центральная FAB)
4. **Оповещения** (с бейджем непрочитанных)
5. **Настройки**

Принципы UX:

- Повторный тап по активной вкладке возвращает в “корень” этой вкладки.
- Для нерутовых экранов вкладка не теряет контекст: маршруты табов кешируются.
- На отдельных маршрутах таб-бар скрывается.

## 3.3 Глобальные feedback-механики

- Toast-сообщения приложения (`info/success/error`).
- Вспышка “Сохранено” при cloud-save-событиях.
- Звуковой feedback на ключевых действиях (navigate/success/error).

## 4. Внутренняя UX-архитектура по модулям

## 4.1 Orders (операционный inbox)

**Цель:** дать менеджеру единый рабочий поток по активным и историческим заказам.

UX-паттерны:

- Сегментация по вкладкам/статусам (active/vip/lead/found/urgent/sold/archive и др.).
- Быстрые сортировки и фильтры.
- Визуальные состояния карточки (в поиске, ждём ответ, найдено, оффер отправлен, продано, архив).
- Swipe-жесты карточек для оперативных действий (контакт, архив и т.д.).
- Микроиндикация “возраста” заказа (NEW / часы / дни).

## 4.2 New Order (захват лида)

**Цель:** максимально быстро создать заказ с телефона.

UX-паттерны:

- Два режима ввода: **quick** и **full**.
- Подсказки бренда/года по VIN.
- Поддержка текста, фото, буфера обмена, голосовых заметок.
- Работа с драфтами заказа.
- Логика локализации коммуникаций по стране/телефону клиента.

## 4.3 Order Details (центр сделки)

**Цель:** полный контроль жизненного цикла заказа в одном экране.

UX-паттерны:

- Управление бизнес-статусами (sales/customer/payment).
- Инструменты коммуникации с клиентом и шаблоны сообщений.
- Управление блоками деталей, фото, заметками, аудио.
- Операции подготовки/шаринга сметы.
- Интеграция диагностических и аналитических элементов (логистика, AI-подсказки и пр.).

## 4.4 Order Parts

**Цель:** быстро оперировать набором деталей внутри заказа.

UX-паттерны:

- Компактный список деталей с визуальными превью.
- Выбор деталей для пакетного шаринга.
- Генерация карточек/шитов с ценами.
- Сохранение скролла экрана между навигационными переходами.

## 4.5 Part Details

**Цель:** управлять офферами по одной детали.

UX-паттерны:

- Карточки вариантов (закуп/продажа, состояние, наличие, ETA, контакты, локация).
- Работа с медиа (фото, вставка из буфера, предпросмотр).
- Маркировка best option.
- Быстрые действия: звонок, мессенджер, карта, share price card.

## 4.6 Suppliers Database

**Цель:** долгосрочная память команды о поставщиках.

UX-паттерны:

- Типизация поставщиков (new parts/scrapyard/dealer/warehouse и т.д.).
- Статусная модель доверия (new → trusted / blacklist).
- Геозоны и геопривязка (в т.ч. промышленные районы).
- История взаимодействий, контакты, связи с деталями.
- Инструменты приоритизации и ручного отбора для радар-флоу.

## 4.7 Variants Library

**Цель:** переиспользование ценовых вариантов между заказами.

UX-паттерны:

- Единая библиотека standalone + order-based вариантов.
- Фильтры (all/standalone/order/pinned/favorite/with_photo).
- Сортировки (updated/created/supplier/price/pinned).
- Быстрое создание через шаблоны цен.
- Поиск и редактирование карточки варианта.

## 4.8 Vendor Slides (launch dashboard)

**Цель:** быстрый запуск режима vendor-slider по релевантным срезам.

UX-паттерны:

- Тёмный командный дашборд с крупными кнопками-срезами.
- Срезы по статусам (срочные/есть варианты/нет вариантов/нет поставщиков/нужно отправить).
- Срезы по зонам Sharjah.
- Срезы по локациям (базовые + пользовательские зоны из settings).
- Срезы по маркам авто.
- CTA “Открыть все слайды”.

## 4.9 Notifications

**Цель:** не терять задачи и контроль follow-up.

UX-паттерны:

- Фильтры по типам событий (orders/radar/follow-up/actions/system/sync).
- Active/archive табы.
- Периоды (today/yesterday/week/all).
- Поиск и сортировки (new/severity).
- Undo сценарии и массовые операции.

## 4.10 Settings

**Цель:** сервисный и операционный контроль системы.

UX-паттерны:

- Облако/локальный режим, диагностика подключений.
- Техобслуживание медиа (storage, дубликаты, blacklist broken images).
- Инструменты синхронизации и восстановления.
- Настройка параметров расчётов и публичных данных.

## 5. Внешняя (публичная) UX-архитектура

## 5.1 Public Order Form

**Цель:** превратить внешнего посетителя в структурированный лид.

Флоу: 4 шага wizard:

1. Автомобиль
2. Детали
3. Контакты и доставка
4. Подтверждение

UX-паттерны:

- Пошаговая валидация.
- Поддержка фото и аудио заметок в заявке.
- Выбор канала связи (WhatsApp/Telegram/Instagram/E-mail/Phone).
- Сохранение draft и механика повторной отправки при сбоях.

## 5.2 Public Quote

**Цель:** показать клиенту финальную оффер-страницу с доверием и ясностью.

Контентные зоны:

- Итоговая цена.
- Позиции и галерея деталей.
- Разбивка стоимости (детали/доставка/упаковка/комиссия/итого).
- Логистика и документы.
- Контакты для подтверждения (в т.ч. WhatsApp CTA).

UX-паттерны:

- RU/EN локализация.
- Чёткая коммерческая структура “что входит в сумму”.
- Call-to-action подтверждения заказа.

## 6. UX-состояния и правила интерфейса

## 6.1 Состояния данных

- Loading / Empty / Error / Success во всех ключевых модулях.
- Работа с offline/online состояниями и очередями повторной отправки.
- Сохранение локальных промежуточных состояний (draft/scroll/cache).

## 6.2 Состояния уведомлений

- Непрочитанные/прочитанные.
- Активные/архивные.
- Возможность восстановления и snooze.

## 6.3 Состояния заказа

- Поиск/ожидание/найдено/оффер отправлен/продано/архив.
- Приоритеты (high/medium/low).
- Доп. статусы оплаты и продаж.

## 7. Навигационная логика и сценарии

## 7.1 Основной внутренний путь

`Orders` → `Order Details` → `Order Parts` → `Part Details` → обратно в `Order Details` → отправка клиентского предложения.

## 7.2 Поставщики

`Orders/Order Details` → `Suppliers` (поиск контактов) + `Variants` (готовые офферы) → обновление детали/заказа.

## 7.3 Vendor flow

`VendorSlides` → выбор фильтра (статус/зона/марка) → `VendorSlider`.

## 7.4 Публичный путь клиента

`Public Order Form` → попадание во внутренний контур обработки → `Public Quote` по персональной ссылке.

---

## 8. Дизайн-подход и UX-тон

- Mobile-first, плотный рабочий UI, минимальные лишние переходы.
- Высокая “операционность”: много быстрых действий с карточек и списков.
- Тёмная/контрастная подача в специализированных экранах (VendorSlides).
- Яркие цветовые сигналы статусов (urgent/found/no supplier и др.).
- Тактильность UX через звуки, анимации и микрофидбек.

## 9. UX-артефакты, которые стоит сразу сделать при разработке с нуля

1. Карта экранов и переходов (flow diagram).
2. Wireframes для 12+ ключевых экранов.
3. Компонентная библиотека (cards/chips/tabs/toasts/modals/buttons).
4. Матрица состояний (loading/empty/error/offline/success) для каждого экрана.
5. Контентные шаблоны текстов статусов/уведомлений/CTA.
6. Clickable prototype на основной сценарий (от лида до публичной сметы).

---

## 10. Краткое резюме

Архитектура UX/UI этого приложения — это мобильная рабочая система продаж/закупки запчастей с двусторонним контуром: внутренний CRM-операционный интерфейс + внешний клиентский витринный интерфейс. Главная ценность UX — скорость действий, прозрачность статусов и бесшовный переход от заявки к финальному коммерческому предложению.
